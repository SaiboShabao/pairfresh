# PairFresh：双腿行情时效检查器

[English](README.md)

一个只依赖 Python 标准库的小工具。读取本地 JSONL 行情记录，检查用于比较的
两条行情是否采集成功、属于当前轮次、仍在有效期内，以及时间差是否超限。

**项目状态：** 新项目，版本 0.1.0。示例均为合成数据，目前没有生产验证、
交易所直连、社区采用规模或长期维护记录。

## 立即运行

需要 Python 3.10 或以上。在项目目录执行：

```bash
python pairfresh.py examples/demo.jsonl --as-of 2026-10-21T04:00:10Z
```

示例包含六条双腿候选记录：一条通过，五条分别因上一轮缓存、过期行情、
采集失败、双腿时间差过大和未来时间戳被拒绝。因为存在拒绝，退出码为 `1`。

逐条结果输出到标准输出，汇总输出到标准错误：

```json
{"mode": "replay", "total": 6, "accepted": 1, "rejected": 5}
```

检查当前行情时，去掉 `--as-of`：

```bash
python pairfresh.py your-snapshots.jsonl --max-age-ms 5000 --max-skew-ms 1000
```

默认在每条记录检查时读取当前 UTC 时间。`--as-of` 明确进入历史回放模式，
回放通过不能说明行情现在仍然新鲜。输出中包含 `live` 或 `replay` 标识。

## 数据格式

每行一个 JSON 对象，格式见 [examples/demo.jsonl](examples/demo.jsonl)。

- 顶层 `pair`：非空的比较对象标识。
- 顶层 `research_cycle`：由调用方提供的当前评估轮次。
- `legs`：恰好两条行情，`name` 非空且不同。
- 每条行情的 `research_cycle`：实际成功取得这份快照的轮次。
- 每条行情的 `fetch_ok`：必须是布尔值 `true`。
- 每条行情的 `timestamp`：原始行情或快照的时间，必须带 `Z` 或明确时区偏移。

轮次可以是非空字符串或整数，类型和值都必须一致，例如整数 `2` 与字符串
`"2"` 不相等。布尔值和浮点数不能作为轮次。

调用方必须如实保留采集结果和原始时间戳，并提供实际当前评估轮次。不要把
旧缓存重新标记成“本轮成功”。优先使用上游行情本身的时间戳，单凭本地请求
完成时间无法识别上游旧数据。本工具检查输入证据，无法独立证明数据来源。

## 判断规则

同时满足以下条件才通过：

1. 对象结构完整，有合法的评估轮次和两条名称不同的行情。
2. 两腿均采集成功，且两腿采集轮次都与评估轮次一致。
3. 两腿都满足 `0 <= 行情年龄 < max_age_ms`；达到有效期即拒绝。
4. 两腿时间差 `<= max_skew_ms`。

默认有效期为 5,000 毫秒，最大时间差为 1,000 毫秒。这些只是示例默认值，
需要按数据源和业务调整。未来时间戳直接拒绝，使用前应同步采集机器时钟。

结果记录具体原因，例如 `cycle_mismatch`、`fetch_not_successful`、`stale`、
`skew_exceeded`、`future_timestamp`，同时记录评估时间、可解析行情的年龄和
可计算的双腿时间差。坏行被拒绝后继续检查下一行，空白行跳过。

退出码：`0` 表示至少有一条记录且全部通过；`1` 表示存在拒绝或输入为空；
`2` 表示参数、文件或编码错误，此时输出可能不完整。输入路径 `-` 表示标准输入。

## 开发与接入

```bash
python -m unittest discover -s tests -v
```

可直接从 `pairfresh.py` 导入 `check_pair`，把采集器输出转换为上述格式。
目前没有对现有交易项目进行自动适配，也没有修改任何交易程序。

通过检查仅说明输入元数据满足这些条件。它不能证明价格正确、订单簿完整、
交易可成交或策略有盈利能力；检查结果也不应在过期后继续复用。
